🛡️ Security Model
🗄️
Row Level Security (RLS)
Enabled on ALL tables with NO policies. Anon key (exposed in frontend) is completely blocked. Service role key (API routes only) bypasses RLS. Client components must use fetch() to API routes — never query Supabase directly.
💳
Stripe Webhook Verification
All webhook events verified via signing secret (whsec_*). Handles payment_intent.succeeded, payment_intent.payment_failed, and charge.refunded events server-side.
🔒
Admin Portal Hidden
No public links to admin. Header, footer, and popups hidden on /admin/* routes. Admin detection only via email blur on customer login form.
📦
USPS Labels Guarded
USPS_ENV=production required for real label creation. Mock labels generated otherwise. Auto-void on cancellation reclaims postage.
🖼️
Print Files Protected
Server validates payment_intent_id exists before accepting print file uploads. Customers never get access to production files.
🔑
Password Handling
All passwords bcrypt-hashed. Password reset via secure token with 1-hour expiry. Case-insensitive email matching via ilike.
⚠️ Known Security Gaps
🚫
No Server-Side Auth Validation
Auth is purely client-side localStorage. No JWTs, no session tokens. Anyone with a valid user ID in localStorage can access protected pages. API routes don't validate caller identity.
🚫
No Rate Limiting
API routes have no rate limiting or abuse prevention. Login, registration, and email endpoints are vulnerable to brute force.
🚫
No Email Verification
Customer registration doesn't verify email addresses. Anyone can register with any email.
